Link previews (Open Graph)

Also called: Open Graph tags, og:image, social cards, Twitter cards, share preview, unfurl

The title, description and image that show up when someone pastes your link into a chat or a post. They come from Open Graph and Twitter card tags in the page's HTML. Without them, the app guesses, and you often get a bare link or the wrong text.

You need it when

  • People share your pages in chats, social posts or emails.
  • You're about to launch or post your site anywhere public.

Skip it when

  • Internal tools nobody will ever share a link to.

Ways to build it

  1. One site-wide card $0

    Make one 1200 by 630 image and add the same og:image to every page, with each page's own title and description.

    Tradeoff: Done in an hour. Every shared page looks the same.

  2. Framework metadata $0

    Use your framework's metadata feature, such as Next.js generateMetadata, to set tags per page.

    Tradeoff: Per page titles and images with little code. Needs server rendering or static pages to work.

  3. Generated images per page $0

    Draw an image per page from its title, with Next.js ImageResponse or a script that runs at build time.

    Tradeoff: Every page gets a custom card. More code, and the images need caching.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add link preview tags to every public page.

Requirements:
- Set og:title, og:description, og:url, og:type and og:image on every public page, plus twitter:card set to summary_large_image.
- Use each page's own title and description. Fall back to the site-wide ones only when a page has none.
- og:image and og:url must be full https URLs built from one configured site address, not hardcoded hosts.
- Use [one site-wide 1200 by 630 image / generated images per page]. Set og:image:width and og:image:height.
- Tags must be in the HTML the server sends. Don't add them with JavaScript after load.
- Don't include private user data in tags on pages behind login.

Acceptance checks (run each and show me the result):
1. Paste three page links into a link preview tester (or a private message to yourself). Each shows the right title, description and image.
2. The page source of each page has og:title, og:description, og:image and og:url, and og:image is a full https URL.
3. The image loads in a private window without logging in, and it's 1200 by 630 pixels or close to it.
4. Pages behind login don't leak private details in their tags.

If you skip it

Your launch post shows a plain link or a random image from the page, and fewer people click it. Some apps cache the first preview they see, so a fix later can take a while to show.

How Derek runs it

Custody Journal's homepage sets Open Graph and Twitter card tags, including the image width and height, all built from one configured site address. It uses one static card image rather than generating one per page.
