LLM evals

Also called: AI evaluation, prompt regression tests, golden set, LLM as a judge, AI testing

A saved set of real inputs with what a good answer must contain or avoid, run every time you change a prompt, model or setting. It turns 'seems fine' into a score you can compare, so upgrades don't quietly break cases that used to work.

You need it when

  • You change prompts or models, or users depend on the AI output being right.

Skip it when

  • Throwaway experiments. Start the set as soon as the feature ships.

Ways to build it

  1. Test cases in your own test suite $0 + API calls

    20 to 100 real inputs with checks in code: required fields, banned phrases, exact labels, length limits. Run in CI or before each prompt change.

    Tradeoff: Simple and fast. Code checks can't judge tone or helpfulness.

  2. An eval tool $0 open source

    promptfoo (open source) runs a test set across prompts and models and shows the results side by side.

    Tradeoff: Good comparisons and reports. Another config format to learn.

  3. Model-graded checks API calls

    A second model scores answers against a short rubric, or the provider's evals tools. Check a sample by hand to make sure the grader agrees with you.

    Tradeoff: Judges open-ended answers. Graders have biases and cost money.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Set up evals for [AI feature].

Requirements:
- Create a test set of [30] real, anonymized inputs, including hard and adversarial ones, stored in the repo.
- For each, write checks: code checks first (schema, required facts, forbidden content, length), then an optional rubric graded by a model for quality.
- One command runs the set against the current prompt and model and prints a pass rate and the failures.
- Save results so I can compare a change with the last run.
- Run it before any prompt or model change is merged, and fail if the pass rate drops more than [5] points.
- Add every bug report about AI output as a new test case.

Acceptance checks (run each and show me the result):
1. One command runs the whole set and prints the score.
2. Breaking the prompt on purpose makes the score drop and the check fail.
3. Running the same set twice gives similar scores.
4. At least 5 test cases come from real failures.

If you skip it

Each prompt tweak or model upgrade fixes one thing and silently breaks three others, and you only hear about it from users.

People describe this as

  • “I changed the prompt and something else got worse”
  • “test my AI feature before switching models”
  • “how do I know if the AI answers are good”
