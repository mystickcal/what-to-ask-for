Debounce and throttle

Also called: debounce, throttle, search as you type, rate limit input, too many requests from typing

Two ways to stop a fast stream of events from doing work every time. Debounce waits until the user pauses, then runs once, which suits search boxes and autosave. Throttle runs at most once every so often, which suits scroll, resize and drag handlers.

You need it when

  • Search or autocomplete that calls an API or database as people type.
  • Handlers on scroll, resize, mouse move or drag that do real work.

Skip it when

  • Buttons and form submits. Disable the button while it runs instead, so a double click can't send twice.

Ways to build it

  1. A small utility $0

    lodash debounce and throttle, or a hook like use-debounce in React. A hand-written debounce is about ten lines.

    Tradeoff: Simple and well tested. Remember to cancel pending calls when the component goes away.

  2. Your framework's built-in delay $0

    htmx hx-trigger with delay: (debounce) or throttle:, or the debounce option in your form or search library.

    Tradeoff: No code to maintain. Less control over edge cases.

  3. Debounce plus cancel the old request $0

    Debounce the input and abort the previous fetch with AbortController when a new query starts.

    Tradeoff: Fixes results arriving out of order. A little more code.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add debouncing to [search box / autocomplete / filter inputs] and throttling to [scroll / resize handlers].

Requirements:
- Debounce input-driven requests by [300] ms so one request goes out after the user pauses.
- Cancel the previous in-flight request with AbortController when a new one starts, and ignore any response that is not for the latest query.
- Throttle [scroll / resize / drag] handlers to at most once every [100] ms.
- Show a small loading state while a debounced search is running.
- Clean up timers and pending requests when the component unmounts or the page changes.
- Use [lodash / use-debounce / htmx delay / a small helper] rather than a new dependency if one already exists.

Acceptance checks (run each and show me the result):
1. Typing a 10 letter word in the search box sends one request, not ten, in the network tab.
2. Results still appear within about half a second after typing stops.
3. Typing fast and then pausing never shows results for an older query on top of the newer one.
4. Scrolling or resizing for 5 seconds runs the handler a bounded number of times, logged in the console.

If you skip it

Your API and database bills grow with every keystroke, rate limits kick in, results flash in the wrong order, and scroll handlers make the page stutter.
