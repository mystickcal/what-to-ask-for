LLM observability

Also called: LLM tracing, AI logging, token usage tracking, LLM monitoring, prompt logging, AI cost tracking

Recording every call your app makes to an AI model: the prompt, the answer, which model, how many tokens, what it cost and how long it took. When an answer is wrong or the bill jumps, you can look up exactly what happened instead of guessing.

You need it when

  • Real users are using an AI feature and you can't reproduce what they saw.
  • Your AI provider bill is growing and you can't tell which feature or user drives it.
  • You change prompts or models and want to know if things got better or worse.

Skip it when

  • You're still testing an AI feature by yourself and can read the responses in your terminal.

Ways to build it

  1. Hosted tracing tool Free tier, then paid by volume

    Langfuse Cloud, Helicone or a similar service, added through their SDK or as a proxy in front of your provider.

    Tradeoff: Fast to set up with a ready dashboard. Your prompts and answers are stored by another company.

  2. Self-hosted tracing $0 plus a server

    Run open source Langfuse yourself, or send OpenTelemetry traces to a backend you already run.

    Tradeoff: The data stays with you. You maintain and back it up.

  3. Your own log table $0

    Save model, token counts, cost, time taken and status for each call in your database, with the user and feature it came from.

    Tradeoff: Simple and private. No trace view, and you build any reporting yourself.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add observability to every AI model call in this app.

Requirements:
- Wrap every call to [OpenAI / Anthropic / our provider] in one shared helper so nothing calls the provider directly.
- For each call record: feature name, user or account ID, model, input and output tokens, cost, time taken, and success or error.
- Send traces to [Langfuse / Helicone / OpenTelemetry / a database table]. Make prompt and response logging a setting I can turn off.
- Never log API keys, passwords, payment details or [other sensitive fields]. Remove them before anything is saved.
- Show users a plain error message when the provider fails. Don't pass the provider's raw error to the browser.
- Add a simple daily total of tokens and cost per feature.

Acceptance checks (run each and show me the result):
1. Make one AI request in the app and find it in the trace view with the model, prompt, response, token counts, cost and time taken.
2. Force the provider to fail (for example a bad API key in a test environment) and confirm the failure is logged and the user sees a plain error message.
3. A per-day cost total can be shown for the last 7 days.
4. Search the logs for an API key or a test password you typed into a prompt and confirm it doesn't appear.

If you skip it

When the AI says something wrong to a customer you have no record of what it was asked, and the first sign of a runaway loop or an abused endpoint is the invoice.

How Derek runs it

Custody Journal saves the total token count on every AI reply and keeps a running total for each conversation. The model call runs in a separate worker process, and if the provider fails the app shows a general error instead of the provider's message, because that message can contain document text.
