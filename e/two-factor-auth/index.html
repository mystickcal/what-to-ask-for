Two-factor authentication (TOTP)

Also called: 2FA, MFA, multi-factor authentication, authenticator app, one-time codes, recovery codes

After the password, the user types a 6-digit code from an authenticator app. You store a secret per user, check codes with a small time window, and give recovery codes for when the phone is gone.

You need it when

  • Accounts hold money, private data, or admin power.
  • Business customers ask for it in security reviews.

Skip it when

  • You only use social login or passkeys, where the provider or device already covers this.

Ways to build it

  1. Your auth library's MFA module $0

    django-allauth MFA, Devise two-factor, Better Auth's two-factor plugin, Laravel Fortify.

    Tradeoff: Tested flows for setup, login and recovery. You follow its screens and storage.

  2. A hosted auth provider free tiers, MFA sometimes paid

    Clerk, Auth0, Supabase Auth, Firebase Auth and WorkOS offer TOTP and often SMS or passkeys.

    Tradeoff: Minutes to turn on. Check which plan includes it.

  3. Build it with a TOTP library $0

    pyotp or otplib for codes, a QR code library for setup, your own tables for secrets and recovery codes.

    Tradeoff: Full control. Easy to miss replay checks, rate limits and recovery.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add optional TOTP two-factor authentication, required for [admins].

Requirements:
- Setup: show a QR code and the secret as text, ask for one valid code before turning it on.
- Store the TOTP secret encrypted. Accept the current code and one step either side (30 seconds) and reject a code that was already used.
- Generate 10 single-use recovery codes, show them once, store only hashes.
- Login: after a correct password, ask for a code or a recovery code. Don't create the full session until it passes.
- Rate limit code attempts per account and per IP.
- Turning 2FA off or making new recovery codes needs the password plus a current code.
- Email the user whenever 2FA is turned on, off, or a recovery code is used.
- Password reset must not turn off 2FA.

Acceptance checks (run each and show me the result):
1. A code from Google Authenticator or 1Password logs in; the same code a second time fails.
2. Each recovery code works once.
3. Ten wrong codes in a row get throttled.
4. Resetting the password still asks for the second factor at login.
5. The database holds no plain recovery codes.

If you skip it

One leaked password is enough to take over an account, or users lock themselves out with no way back.

People describe this as

  • “add 2FA with Google Authenticator”
  • “require a code from an app after the password”
  • “lost my authenticator device and can't log in”
  • “make admins use two-factor”
