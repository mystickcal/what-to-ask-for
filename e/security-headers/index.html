Security headers (CSP, HSTS)

Also called: Content Security Policy, HSTS, X-Frame-Options, clickjacking protection, HTTP security headers

Response headers that tell the browser how strict to be with your pages: HTTPS only (HSTS), who may frame you, which scripts and connections are allowed (CSP), and what features like the camera or location are off.

You need it when

  • Any app with logins or private data.
  • A customer security review or scanner flags missing headers.

Skip it when

  • Never fully. Even a static site benefits from HSTS and nosniff.

Ways to build it

  1. Your framework's security settings $0

    Django SECURE_* settings and a CSP middleware, Helmet for Express, Next.js headers config, Rails content_security_policy.

    Tradeoff: Lives with the code and is tested with it. CSP takes some tuning.

  2. Set them at the proxy or CDN $0

    Nginx, Caddy or Traefik headers, Cloudflare Transform Rules, or _headers files on Netlify and Cloudflare Pages.

    Tradeoff: One place for all routes. Easy to forget when the app moves.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add security headers to my app and tune them so nothing breaks.

Requirements:
- Strict-Transport-Security: max-age=31536000; includeSubDomains (preload only once I'm sure every subdomain is HTTPS).
- X-Content-Type-Options: nosniff. Referrer-Policy: strict-origin-when-cross-origin.
- Clickjacking: Content-Security-Policy frame-ancestors 'none' (or 'self') plus X-Frame-Options DENY for older browsers.
- Permissions-Policy turning off camera, microphone and geolocation unless a page needs them.
- A Content-Security-Policy with default-src 'self', object-src 'none' and base-uri 'self', listing the outside script, style, font, image and connect sources the app really uses.
- Start CSP in Report-Only mode for [a week], collect violations, then enforce.
- Prefer nonces over 'unsafe-inline' for scripts; list any inline scripts that block this.
- Add a test that checks the headers on the home page, a logged-in page and an API response.

Acceptance checks (run each and show me the result):
1. securityheaders.com or Mozilla Observatory shows an A or better.
2. The app can't be loaded in an iframe on another origin.
3. No CSP violations show in the console on main pages after enforcing.
4. HTTP requests redirect to HTTPS and repeat visits go straight to HTTPS.
5. The header test runs in CI.

If you skip it

Your app can be framed for clickjacking, injected scripts run freely, and security reviews stall on easy findings.

How Derek runs it

Custody Journal sets HSTS for a year with includeSubDomains and preload in production, nosniff, and X-Frame-Options DENY. A middleware adds a CSP with frame-ancestors 'none', object-src 'none' and base-uri 'self', plus a Permissions-Policy that turns geolocation off. The CSP is deliberately loose about inline scripts so it can't break the live UI.

From the Custody Journal code and release runbook, read 2026-10-21.
