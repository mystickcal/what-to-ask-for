AI spend caps and token budgets

Also called: AI cost control, token limits, usage quota, max tokens, spend limit, monthly AI allowance

Putting a ceiling on AI spending at every level: maximum tokens per request, an allowance per user or plan, and an alert or hard stop for the whole account. Record usage for each call so you know which features and users cost what.

You need it when

  • Users can trigger model calls, especially on free plans.

Skip it when

  • Internal tools with a few trusted users and a provider spend limit set.

Ways to build it

  1. Per-request limits and usage logging $0

    Set max output tokens on every call, trim long inputs, and save the token counts the API returns with each request.

    Tradeoff: Necessary first step. Doesn't stop many small calls adding up.

  2. A per-user allowance in your database $0

    Count requests or tokens per user per month by plan. Reserve before the call inside a locked transaction, and refund if the call never starts.

    Tradeoff: Fair and plan-aware. Needs care so parallel requests can't overspend.

  3. Provider and gateway limits $0, included

    Set budget alerts and project limits in the provider dashboards, or per-key budgets in a gateway like LiteLLM.

    Tradeoff: A safety net for bugs and leaked keys. Too blunt to be the only control.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add AI cost controls to this app.

Requirements:
- Set max output tokens on every model call, and cap input size (truncate or refuse long inputs with a message).
- Log every call: user id, feature, model, input and output tokens, and estimated cost.
- Give each plan a monthly allowance ([Free: 20 requests, Pro: 500]). Reserve one unit before the call inside a transaction with the user's row locked, so parallel requests can't overspend. Refund the reservation if the call never starts.
- A client-supplied request id makes retries count once.
- Show users how much allowance is left and what happens when it runs out.
- Add an admin view of spend by feature and top users this month.
- Remind me to set budget alerts and a hard limit in the provider dashboard.

Acceptance checks (run each and show me the result):
1. 20 parallel requests from a user with 5 left succeed exactly 5 times.
2. Retrying with the same request id doesn't use a second unit.
3. A user at their limit gets a clear message and no model call is made.
4. The admin view totals match the provider's usage page within a few percent.

If you skip it

One user or one bug runs up a bill bigger than your revenue, and you can't tell which feature did it.

How Derek runs it

Custody Journal gives its Protected plan a monthly AI allowance (50 requests unless configured otherwise) and its Advocate plan unlimited use. Each request reserves a slot while the user's row is locked, using a client-supplied request id: a retry with the same id isn't charged twice, and the same id with different inputs is refused. Reservations that haven't started after 5 minutes are refunded, and the month is counted in the user's own time zone.
