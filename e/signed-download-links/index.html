Signed download link

Also called: presigned URL, expiring link, signed URL, private file link, temporary download URL

A URL with an expiry time and a signature built in. Anyone with the link can download until it expires, and changing any part of it breaks the signature. The files stay private by default.

You need it when

  • User uploads, invoices, exports, paid downloads, anything you don't want indexed or shared forever.

Skip it when

  • The files are meant to be public, like marketing images or open docs.

Ways to build it

  1. Presigned URLs from object storage storage cost, or $0 self-hosted

    S3, Cloudflare R2, DigitalOcean Spaces and self-hosted MinIO or Garage all support S3-style presigned GET links.

    Tradeoff: Fast and offloads bandwidth. Anyone holding the link can use it until it expires, so keep expiry short.

  2. Your app checks access and streams the file $0

    Check login and ownership, then send the file, or hand it to the proxy with X-Accel-Redirect or X-Sendfile.

    Tradeoff: Access is checked on every download. Large files tie up app workers unless the proxy serves them.

  3. Sign your own links $0

    Django signing (TimestampSigner), Rails signed ids, or a JWT with an exp claim on a download route.

    Tradeoff: You write the checks yourself. Rotating the key kills every outstanding link, which is sometimes what you want.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Serve [file type] privately with expiring download links.

Requirements:
- The bucket or folder is private. No public ACLs or public bucket policy.
- When a logged-in user asks for a file, check they own it, then create a presigned GET URL that expires in [15 minutes].
- Set Content-Disposition so it downloads with a safe filename.
- Keep the storage keys on the server. The frontend only ever gets the short-lived URL.
- Log who created a link for which file and when. Don't log the URL itself.

Acceptance checks (run each and show me the result):
1. The object's plain URL without a signature returns 403.
2. A new link works, then returns 403 after it expires.
3. Changing one character of the path or signature returns 403.
4. User A can't get a link to user B's file by changing the id.
5. Signed URLs don't show up in server logs or analytics.

If you skip it

Private files get indexed, guessed or shared forever, and you can't take a link back.

People describe this as

  • “let a user download their file without making it public”
  • “the PDF link should stop working after a day”
  • “the files in my bucket are public”
  • “share a private file with one person”
