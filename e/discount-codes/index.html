Discount codes

Also called: coupon codes, promo codes, promotion codes, coupons, launch discount, voucher codes

Codes customers type at checkout to get money off, and the rules behind them: how much, for how long, for whom, and how many times. Payment platforms keep the rules on their side, so a code can't be faked from the browser.

You need it when

  • You're launching and want to reward early buyers.
  • You give creators or partners their own codes and want to see what each one brings in.
  • Your sales team gives some customers a special price.

Skip it when

  • You don't plan to offer discounts. Then leave the code box off your checkout.

Ways to build it

  1. Your payment platform's promo codes $0 extra

    Create coupons and promotion codes in Stripe, Paddle or Lemon Squeezy and turn on the code field in their checkout. Stripe's allow_promotion_codes adds the box.

    Tradeoff: Limits, expiry and first order rules are built in. You're tied to their checkout and their rules.

  2. Discounts applied by your server $0 extra

    Your code decides who gets a deal and applies a coupon to their subscription or checkout, so the customer never types anything.

    Tradeoff: Good for sales deals and win back offers. No shareable code, so it doesn't help with promotions.

  3. Your own discount table $0

    Store codes, amounts, expiry, use limits and redemptions in your database and work out the price yourself.

    Tradeoff: Full control. Easy to get rounding, stacking and race conditions wrong, and the payment record has to match your math.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add discount codes to checkout.

Requirements:
- Use [Stripe promotion codes / Paddle discounts / Lemon Squeezy discounts]. Keep every rule on the payment platform or the server, never in the browser.
- Codes can be a percentage or a fixed amount, last [once / for N months / forever], expire on a date and have a total use limit.
- Support a first order only rule and codes tied to one customer.
- Show a clear message for codes that are wrong, expired or used up, and don't change the price.
- Save the code and the amount it took off on each order, so I can report sales per code.
- Two people using the last remaining use of a code at the same moment: only one gets it.

Acceptance checks (run each and show me the result):
1. Enter a valid code at checkout. The total drops by the right amount before payment.
2. Enter an expired code, a used up code and a made up code. Each one is refused with a clear message and the price doesn't change.
3. A code limited to first orders is refused for a customer who has bought before.
4. The order or invoice shows which code was used and how much it took off.

If you skip it

Launch deals and partner codes turn into manual refunds after the sale, and a code shared too widely can't be shut off or tracked.

People describe this as

  • “add a coupon code box to my checkout”
  • “give a launch discount for the first 100 customers”
  • “make a promo code for an influencer”
