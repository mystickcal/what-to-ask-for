Dependency updates and audits

Also called: Dependabot, Renovate, npm audit, pip-audit, vulnerable packages, supply chain security

A routine for keeping third-party packages current and checked against known vulnerabilities: pinned versions in a lockfile, automatic update pull requests, and an audit step that fails the build on serious issues.

You need it when

  • Your app uses packages from npm, PyPI or any registry, which is nearly every app.

Skip it when

  • Never. Throwaway prototypes can skip the routine, not the lockfile.

Ways to build it

  1. Dependabot free on GitHub

    Turn on Dependabot alerts and security updates, and add a dependabot.yml for weekly version updates.

    Tradeoff: Built in. Can open a lot of pull requests unless you group them.

  2. Renovate free

    The Renovate app or self-hosted runner opens grouped update pull requests with automerge rules for safe updates.

    Tradeoff: Very configurable. The config takes some learning.

  3. Audit commands in CI $0

    npm audit --audit-level=high, pip-audit, osv-scanner or bundler-audit run on every push.

    Tradeoff: Catches known issues before deploy. Doesn't update anything for you.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Set up dependency updates and vulnerability audits for this repo.

Requirements:
- Make sure every dependency is pinned in a committed lockfile.
- Add [Dependabot / Renovate] config: weekly, grouped minor and patch updates, separate pull requests for majors, security updates right away.
- Add CI steps: [npm audit --audit-level=high], [pip-audit -r requirements.txt] (or osv-scanner for both). Fail the build on high or critical.
- Tests must run on update pull requests. Automerge only patch updates that pass.
- Document how to handle an audit failure with no fix yet (pin, replace, or record an exception with an expiry date).
- List current high and critical findings and fix or explain each.

Acceptance checks (run each and show me the result):
1. Adding a package with a known high vulnerability fails CI.
2. An update pull request appears within a week and runs the tests.
3. Every dependency file has a lockfile next to it.
4. Current audit output has no unexplained high or critical findings.
5. Exceptions have an owner and expiry date.

If you skip it

A known hole in an old package stays in production for months, or a year of skipped updates turns into one painful upgrade.

How Derek runs it

Custody Journal's release gate runs pip-audit against requirements.txt and npm audit with --audit-level=high on its lockfiles, and the release stops if either fails.
