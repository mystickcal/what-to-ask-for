Password reset tokens

Also called: forgot password, reset link, password recovery, reset token

A one-time, short-lived link emailed to the account owner that lets them set a new password. The token is random and stored only as a hash (or signed), and it stops working after use, after it expires, and once the password changes.

You need it when

  • Your app has passwords.

Skip it when

  • You don't store passwords at all: login is only by magic link or social login.

Ways to build it

  1. Your framework's built-in reset $0

    Django's PasswordResetView (tokens stop working once the password changes and expire after PASSWORD_RESET_TIMEOUT, 3 days by default), Laravel's password broker, or the Rails authentication generator.

    Tradeoff: Tested and maintained. Shorten the expiry and add rate limits yourself.

  2. Your auth provider's reset flow free tiers

    Supabase Auth, Clerk, Auth0 and Firebase Auth send and check reset emails for you.

    Tradeoff: Nothing to build. Their emails and pages may not match your brand without setup.

  3. Your own reset tokens table $0

    Generate 32 random bytes, email the raw token, store only its SHA-256 hash with an expiry and a used_at time.

    Tradeoff: Full control. Easy to miss one rule: expiry, single use, or the same reply for unknown emails.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add a password reset flow.

Requirements:
- The request form always shows the same message ('If an account exists for that email, we sent a link'), whether or not the email exists.
- Rate limit requests per IP and per email.
- Token: random from a secure generator, at least 32 bytes. Store only a hash, with expires_at [30 minutes] and used_at.
- Build the link from our configured site URL, never from the request's Host header.
- The reset page sets Referrer-Policy: no-referrer so the token doesn't leak to other sites.
- Using the link marks it used. A new request cancels older unused tokens. Changing the password ends the user's other sessions.
- Send a 'your password was changed' email afterwards.

Acceptance checks (run each and show me the result):
1. Requesting a reset for an unknown email shows the same message and takes about the same time as a known one.
2. A link works once, and the second use shows 'invalid or expired'.
3. A link older than the expiry fails.
4. The database holds no raw tokens.
5. After a reset, a session logged in on another browser is logged out.

If you skip it

Old reset emails become a way into accounts, and the form leaks which emails are registered.

People describe this as

  • “add a forgot password link”
  • “reset links never expire”
  • “the reset page tells people which emails have accounts”
  • “someone used an old reset email to get into an account”
  • “log out other devices after a password change”
