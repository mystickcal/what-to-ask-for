Text to speech

Also called: TTS, read aloud, AI voice, voice generation, speech synthesis, narration

Turning written text into spoken audio, from a free voice built into the browser or a natural sounding AI voice from an API. The backend part is mostly about cost: make each piece of audio once, save it, and play the saved file after that.

You need it when

  • People want to listen to articles, lessons or replies instead of reading.
  • You're adding a voice to an AI assistant.
  • Accessibility matters for your users.

Skip it when

  • Short labels and buttons. Screen readers already handle those.

Ways to build it

  1. Browser speech $0

    The Web Speech API's speechSynthesis reads text aloud with the voices on the user's device.

    Tradeoff: Free and instant. Voices differ by device and can sound robotic, and there's no file to save.

  2. Voice API Paid per character or per minute

    Send text from your server to OpenAI's speech endpoint, ElevenLabs or a similar service, save the audio and play it.

    Tradeoff: Natural voices. Costs grow with every new piece of text, and models and voices get retired, so check before you build on one.

  3. Open model on your server $0 plus compute

    Run an open text to speech model such as Piper on your own machine.

    Tradeoff: No per use bill and text stays with you. Lower quality than the best APIs, and you maintain it.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add text to speech to [articles / assistant replies].

Requirements:
- Use [the browser's speechSynthesis / OpenAI's speech API / ElevenLabs]. Call any paid API from the server only, never with a key in the browser.
- Save generated audio in [object storage] keyed by a hash of the text, voice and model. Play the saved file when it exists.
- Make new audio when the text changes, and delete audio that's no longer used.
- Stream or start playback before the whole file is done for long text, or split long text into parts.
- Limit how much text one user can turn into audio per day.
- Tell listeners the voice is AI generated.

Acceptance checks (run each and show me the result):
1. Press play on a 500 word article. Audio starts within a few seconds and sounds right in the chosen voice.
2. Play the same article twice. The second time comes from the saved file and makes no new API call.
3. Edit the text and play it again. It makes new audio instead of reading the old version.
4. With the voice service failing, the user sees a plain error and can still read the text.

If you skip it

Each play of the same article costs you again, a busy day turns into a surprise bill, and listeners may not know the voice isn't a person, which some providers' rules require you to say.

People describe this as

  • “add a listen button that reads my articles out loud”
  • “turn text into speech in my app”
  • “give my AI assistant a voice”
