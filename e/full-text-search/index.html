Full-text search

Also called: site search, search box, Postgres full-text search, Meilisearch, typo-tolerant search

Search that matches words, not exact strings: it handles plurals and word forms, ranks the best matches first, and stays fast as data grows. Postgres can do this well before you need a separate search engine.

You need it when

  • Users need to find records by words in titles or bodies, and LIKE queries are slow or miss obvious matches.

Skip it when

  • Small lists where filtering in the browser is instant.

Ways to build it

  1. Postgres full-text search $0

    A generated tsvector column with a GIN index, queried with websearch_to_tsquery and ranked with ts_rank. Add pg_trgm for typo-tolerant name matching.

    Tradeoff: No new service, and results respect your normal permissions. Typo tolerance and instant search-as-you-type take extra work.

  2. Meilisearch or Typesense $0 self-hosted, paid cloud

    A search engine you run next to your app. Sync records to it on save, and filter by owner or tenant in every query.

    Tradeoff: Fast, typo-tolerant and good for instant search. Another service to sync and secure.

  3. Hosted search paid, free tiers

    Algolia or the cloud editions of Meilisearch and Typesense.

    Tradeoff: Least setup. Your data lives with a vendor, and costs grow with records and searches.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add full-text search to [model] in this app.

Requirements:
- Use Postgres full-text search: a generated tsvector column over [title (weight A), body (weight B)] with a GIN index.
- Parse user input with websearch_to_tsquery so quotes and minus signs work and odd input can't cause errors.
- Rank with ts_rank and show a highlighted snippet with ts_headline.
- Filter results by the current user's or tenant's access in the same query.
- Add pg_trgm similarity on [names] for typo tolerance.
- Paginate results and debounce the search box.

Acceptance checks (run each and show me the result):
1. Searching 'running' finds a post containing 'runs'.
2. Searching a misspelled name still finds it.
3. EXPLAIN shows the GIN index is used.
4. User B never sees user A's records in results.
5. Input like ') OR 1=1' returns normal results, not an error.

If you skip it

Search that misses obvious matches, slows down as data grows, or shows other users' records.

How Derek runs it

Most Custody Journal record text is encrypted, so the database can't search it. Its search first limits to the user's own records and filters, then decrypts and scans a bounded window of recent candidates in the app and ranks the matches.
