Autosave and drafts

Also called: autosave, auto save, save draft, unsaved changes, lost my work

Saving what a user is writing every few seconds without them pressing Save, usually as a draft that only becomes the real record when they finish. A refresh, crash or dead battery then costs them a few seconds of typing, not the whole thing.

You need it when

  • Long forms, editors, or anything people type into for more than a minute.
  • Users write on phones, where tabs get killed in the background.

Skip it when

  • Short forms of a few fields. A warning before leaving the page is enough.

Ways to build it

  1. Save to the browser $0

    Write the form to localStorage on a short debounce and restore it on load. Clear it after a real save.

    Tradeoff: No server changes and works offline. Lost if they switch devices or clear the browser.

  2. Server-side draft $0

    Post the content on a debounce to a draft endpoint that updates one draft row per user and record, then promote it on Save.

    Tradeoff: Survives any device or crash. You must keep drafts out of every list, count and export.

  3. An editor with built-in autosave $0 to paid

    Rich text or form libraries that ship an autosave plugin, or collaborative editors that save every change.

    Tradeoff: Least code. Ties you to that editor's storage model.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add autosave with drafts to [form / editor].

Requirements:
- Save the content [2] seconds after the user stops typing, and when the field loses focus or the page is hidden.
- Store it as a draft, one draft per user per [record], updated in place instead of a new row each time.
- Keep drafts out of normal lists, search, exports, notifications and usage limits until the user presses Save.
- Show a small status near the form: Saving, Saved, or a clear error if it failed.
- If the record changed somewhere else since it was loaded, stop autosaving and show a conflict message instead of overwriting.
- Warn with beforeunload only when there are changes that have not been saved yet.

Acceptance checks (run each and show me the result):
1. Typing in the form, waiting 3 seconds and refreshing brings the text back.
2. The save status changes from Saving to Saved, and to an error when the network is off.
3. Autosaving 20 times leaves one draft, not 20 records.
4. Drafts don't show in lists, search, exports or usage counts until the user presses Save.
5. Editing the same record in two tabs shows a conflict message instead of silently overwriting.

If you skip it

People lose long pieces of writing to a refresh or a dropped connection, and they rarely come back after that. Done carelessly, half-finished drafts show up as real records.

How Derek runs it

The Custody Journal entry form autosaves about 2 seconds after typing stops. Each user gets one draft per custody case, drafts are hidden from every list and report and don't count against the free plan, and the draft becomes a real entry only when the user presses Save. Autosave stops with a warning if the entry changed elsewhere, and it never rewrites an entry that has already been sealed.
