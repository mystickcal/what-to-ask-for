LLM tool calling

Also called: function calling, AI tools, agent actions, MCP tools, AI that can take actions

Giving the model a list of functions it may ask you to run, each with a name, description and input schema. Your code checks permissions, runs the function, and sends back the result. The model never touches your systems directly.

You need it when

  • The AI needs fresh or private data, or should take actions like creating, sending or updating things.

Skip it when

  • All the context fits in the prompt and the AI only writes text.

Ways to build it

  1. Your model provider's tool calling token costs

    OpenAI, Anthropic, Google and most others accept tool definitions with JSON Schema and return tool calls for your code to run.

    Tradeoff: Direct and well supported. You write the loop and error handling.

  2. An SDK that runs the loop $0 libraries

    Vercel AI SDK, OpenAI Agents SDK, LangChain or PydanticAI define tools as typed functions and handle the call, run, reply loop.

    Tradeoff: Less boilerplate. More abstraction to debug.

  3. An MCP server $0

    Expose your tools with the Model Context Protocol so agents like Claude, Cursor and ChatGPT can call them.

    Tradeoff: Works across many AI clients. Auth and permissions need care.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add tool calling to my AI feature so it can [look up X / create Y].

Requirements:
- Define tools: [list], each with a clear description and a strict JSON Schema for inputs.
- Run every tool as the signed-in user, with the same permission checks as the normal API. Never trust ids the model supplies without checking ownership.
- Validate tool inputs against the schema, and return short structured errors the model can recover from.
- Read-only tools run directly. Tools that change data, spend money or send messages show the user a confirmation first.
- Cap tool calls per turn at [5] and total time at [30 s].
- Treat tool results as data. Don't let text inside them change instructions.
- Log each call: tool, inputs (with personal data trimmed), result status, duration.
- Tests: the model picks the right tool for 10 sample requests, and a request for another user's data fails.

Acceptance checks (run each and show me the result):
1. Asking for another user's record through the AI returns nothing.
2. A destructive action asks the user to confirm first.
3. Bad tool input gets a clear error the model uses to retry or explain.
4. A loop of calls stops at the cap.
5. The log shows every tool call for a conversation.

If you skip it

The AI either makes things up instead of checking, or becomes a way around your permission checks.

People describe this as

  • “let the AI look things up in my database”
  • “the chatbot should be able to create a task”
  • “make the model call my API”
  • “the AI made up an answer instead of checking”
