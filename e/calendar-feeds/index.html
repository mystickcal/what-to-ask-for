Calendar feeds and invites (ICS)

Also called: iCal feed, ICS file, subscribe to calendar, add to calendar, webcal link, recurring events

Publishing events in the iCalendar format so Google, Apple and Outlook calendars can show them. A one-off .ics file adds a single event. A private subscription URL lets the user's calendar refresh your events on its own schedule.

You need it when

  • Your app has dates users care about: bookings, deadlines, schedules, classes, shifts.

Skip it when

  • You need two-way sync (edits in Google flowing back). That needs the calendar APIs and OAuth, not a feed.

Ways to build it

  1. A private ICS subscription URL $0

    A URL with a long random token returns text/calendar for that user. Calendar apps poll it.

    Tradeoff: Works everywhere with no OAuth. Google can take hours to refresh, and the URL is the password.

  2. One-off .ics files and email invites $0

    A download or email attachment with one VEVENT for "add to calendar".

    Tradeoff: Simple. Later changes don't reach the calendar unless you send an update.

  3. Calendar APIs $0, OAuth review needed

    Google Calendar API, Microsoft Graph or a unified API like Nylas or Cronofy write events into the user's calendar.

    Tradeoff: Instant and two-way. OAuth setup, scopes review and token storage.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add a private calendar subscription feed (ICS) for each user.

Requirements:
- URL: /calendar/feed/<token>.ics with a random token of at least 32 bytes stored on the user. No session needed. Unknown token returns 404.
- Settings page shows the link (plus a webcal:// version and Google and Apple instructions) and a "reset link" button that issues a new token.
- Return text/calendar; charset=utf-8. Each event has a stable UID, DTSTAMP, start and end, and SUMMARY. Escape commas, semicolons and newlines, and fold lines at 75 octets.
- Use the user's timezone with a VTIMEZONE block, or UTC times. All-day events use DATE values with an exclusive end date.
- Recurring items use RRULE inside a bounded window instead of expanding forever.
- Limit the feed to a window such as [1 year back, 2 years ahead]. Keep private notes out of the feed.
- Cache-Control: private. Validate output with an iCalendar validator in a test.

Acceptance checks (run each and show me the result):
1. Google Calendar, Apple Calendar and Outlook all subscribe and show the events.
2. A weekly event stays at the same local time across the daylight saving change.
3. Resetting the link makes the old URL return 404.
4. Private notes never appear in the feed.
5. The feed passes an iCalendar validator.

If you skip it

Events land an hour off twice a year, feeds leak private details to anyone with the link, or old links can't be shut off.

How Derek runs it

Custody Journal offers a private calendar subscribe URL authenticated by a random token, with a reset button that issues a new one. The feed is served as text/calendar with Cache-Control private, includes VTIMEZONE blocks, uses RRULE for weekly activities inside a window of about 30 days back and a year ahead, and can be limited to one case or child.
