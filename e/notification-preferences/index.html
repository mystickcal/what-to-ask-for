Notification preferences and inbox

Also called: notification settings, in-app notifications, notification center, bell icon, quiet hours, digest emails

A per-user record of which notification types they want on which channel (email, push, in-app), and an in-app list of recent notifications with read state. Every send checks the preferences first.

You need it when

  • You send more than two or three kinds of notifications.
  • Users ask how to get fewer emails.

Skip it when

  • You only send receipts and password resets. Those are transactional and always go out.

Ways to build it

  1. Preferences table and notifications table $0

    One row per user with a toggle per type and channel, plus a notifications table for the in-app list. A single notify() function checks preferences.

    Tradeoff: Simple and private. You build the bell UI and digests.

  2. A notification platform free tiers, then paid

    Knock, Novu, Courier or MagicBell store preferences, render an in-app inbox component and route to email, SMS and push.

    Tradeoff: Fast and full-featured. User activity data goes to a vendor.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add notification preferences and an in-app notification list.

Requirements:
- List every notification type the app sends: [types]. Mark which are transactional (always sent) and which are optional.
- Preferences per user: a toggle per optional type and channel (email, in-app, push), sensible defaults, and quiet hours in the user's timezone with an override for urgent ones.
- One notify(user, type, data) function. It checks preferences and quiet hours, writes the in-app row, and queues the email or push. Nothing else sends notifications directly.
- In-app: bell icon with unread count, list with mark read and mark all read, newest first, paginated.
- Optional digest: group low-priority types into one [daily / weekly] email.
- Every optional email links straight to the preferences page.

Acceptance checks (run each and show me the result):
1. Turning off one type stops that email but leaves the others.
2. Nothing optional is sent during quiet hours; urgent items still go out if allowed.
3. Searching the code shows no sends that bypass notify().
4. Unread count updates after marking items read.
5. Password reset and receipts still send with everything turned off.

If you skip it

Users mute you completely, or mark you as spam, because the only choice is all or nothing.
