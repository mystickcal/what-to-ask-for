Push notifications

Also called: web push, browser notifications, service worker push, VAPID, FCM, APNs, mobile push

Messages that appear on a device even when your app isn't open. On the web, a service worker receives them through the browser's push service, signed with your VAPID keys. iPhones support web push only for sites added to the home screen (iOS 16.4 and later). Native apps use APNs (Apple) and FCM (Google).

You need it when

  • Something time-sensitive happens and email is too slow: a message, a reminder, an order update.

Skip it when

  • The update can wait for the next visit or an email. Unwanted pushes get turned off fast.

Ways to build it

  1. Standard web push from your server $0

    A service worker, the Push API, VAPID keys, and the web-push library (Node) or pywebpush (Python) to send.

    Tradeoff: No third party. On iPhone it only works after the user adds your site to the home screen.

  2. Firebase Cloud Messaging free

    One API for Android, web and iOS (through APNs). Common for native and hybrid apps.

    Tradeoff: A Google account and SDK in your app. Apple setup is still needed for iOS.

  3. A hosted notification service free tiers

    OneSignal, or Novu (open source, self-hostable) for push, email and in-app messages from one place.

    Tradeoff: Dashboards and scheduling built in. Another vendor holds your device tokens.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add web push notifications for [event].

Requirements:
- Ask for permission only after the user clicks 'Turn on notifications', never on page load.
- Generate VAPID keys once and keep the private key in an environment variable.
- Save each subscription (endpoint and keys) per user and device. Delete it when the push service answers 404 or 410.
- Send from a background job, not the web request.
- Notification text says what happened and links to the right page. No sensitive details on the lock screen.
- A settings page lets users turn push off per type and see their devices.

Acceptance checks (run each and show me the result):
1. Loading the site doesn't show a permission prompt.
2. After opting in on desktop Chrome, a test event shows a notification with the site closed.
3. On an iPhone with the site added to the home screen, the same test works.
4. A subscription that returns 410 is deleted and not retried.
5. Turning a type off stops those notifications on all devices.

If you skip it

Permission prompts on page load get blocked for good, and dead subscriptions pile up and slow every send.

People describe this as

  • “notify users even when the site is closed”
  • “send a phone notification from my web app”
  • “do push notifications work on iPhone”
  • “stop sending to people who turned notifications off”
