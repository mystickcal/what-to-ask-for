PDF generation

Also called: generate PDF, HTML to PDF, invoice PDF, PDF reports, export to PDF

Turning your data into a PDF file users can download, print or send. Either render HTML with a headless browser or a print-CSS engine, or draw the document directly with a PDF library. Big documents go to a background job.

You need it when

  • Invoices, receipts, reports, certificates or anything users print or hand to someone else.

Skip it when

  • A print stylesheet on the web page is enough and users can "Save as PDF" themselves.

Ways to build it

  1. Headless Chromium $0, needs memory

    Playwright or Puppeteer load an HTML page and call page.pdf().

    Tradeoff: Matches your web styling. Heavy to run, and pages must not load untrusted URLs.

  2. A print-CSS engine $0

    WeasyPrint (Python) renders HTML and CSS to PDF without a browser, with good page headers and footers.

    Tradeoff: Lighter than Chromium. No JavaScript, and some modern CSS is missing.

  3. Draw it with a PDF library $0

    ReportLab (Python), PDFKit or pdf-lib (JavaScript), or React-PDF lay out text and tables in code.

    Tradeoff: Fast and exact. Layout changes take code.

  4. A PDF API free tiers, then per document

    Services such as DocRaptor or PDFShift convert HTML for you.

    Tradeoff: Nothing to host. Your documents leave your servers.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add PDF generation for [document type] using [tool].

Requirements:
- Build the PDF from a template plus data, in a background job if it takes over [3 seconds].
- Page size [Letter / A4], margins, page numbers in the footer, and a header with the date generated.
- Embed fonts so it looks the same everywhere. Tables split across pages with the header row repeated.
- Escape all user text. If rendering HTML in a browser, block network requests except my own static files.
- Store the file privately and serve it through a signed or owner-checked link.
- Set a filename like [invoice-2026-001.pdf] and Content-Disposition attachment.
- Add a test that generates a sample and checks the page count and some text.

Acceptance checks (run each and show me the result):
1. A 30-page report generates without timing out the web request.
2. User text with HTML tags appears as text, not markup.
3. Another user can't download the file by changing the id.
4. The PDF opens correctly in Acrobat, Preview and Chrome.
5. Long tables repeat their header on each page.

If you skip it

Requests time out on big documents, a user's text injects markup into an invoice, or private PDFs are readable by anyone with the link.
