Speech to text

Also called: voice input, dictation, transcription, Whisper, voice notes, Web Speech API

Turning spoken words into text, either live while the user talks or from an uploaded recording. You can use the browser's built-in speech recognition for free, send audio to a transcription API, or run an open model like Whisper yourself.

You need it when

  • Users write long notes, often on a phone, where typing is slow.
  • People already have recordings, like voice memos or calls, they want as text.
  • Accessibility matters for your users.

Skip it when

  • Short form fields where typing is quicker, or anywhere a wrong word could change the meaning and nobody will check it.

Ways to build it

  1. Browser speech recognition $0

    The Web Speech API's SpeechRecognition turns microphone input into text live.

    Tradeoff: Free and instant. Support varies by browser, and some browsers send audio to their own servers.

  2. Transcription API Paid by the minute of audio

    Send uploaded or recorded audio from your server to OpenAI's speech to text API or a similar service.

    Tradeoff: Accurate and works with files. Costs money, has file size limits, and the audio goes to the provider.

  3. Run Whisper yourself $0 plus compute

    Run the open source Whisper model (or a faster port of it) on your own server or the user's device.

    Tradeoff: Audio stays with you. Slow without a decent machine, and you maintain it.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add speech to text to [the notes field / this form].

Requirements:
- Add a microphone button that uses [the browser's SpeechRecognition / recording plus our transcription API]. Hide or disable it in browsers that don't support it.
- For uploads, accept [MP3, WAV, M4A] up to [25 MB] and check type and size before sending anything.
- Call the transcription service from the server with a timeout, never with an API key in the browser.
- Put the text into the field so the user can edit it before saving. Never save it automatically.
- Delete uploaded audio after transcription unless the user chooses to keep it.
- Show a clear message when transcription fails, and keep whatever the user already typed.

Acceptance checks (run each and show me the result):
1. Record 30 seconds of speech on a phone and on a laptop. The text appears and can be edited before saving.
2. Upload an audio file over the size limit. The app refuses it with a clear message before sending it anywhere.
3. With the transcription service turned off or failing, the user sees a plain error and what they already typed is still there.
4. The audio file isn't kept after transcription unless the user chose to save it.

If you skip it

Users who'd rather talk give up on long entries, or type into another app and paste. Done carelessly, audio piles up on your server or an API key ends up in the browser.

How Derek runs it

Custody Journal has two ways in. Speak to type uses the browser's built-in speech recognition, which the app says works in Chrome and Edge. Uploads of MP3, WAV or M4A files up to 25 MB go from the server to OpenAI's whisper-1 model with a 60 second timeout and one retry, and the transcript is added to the entry so the user can edit it.
