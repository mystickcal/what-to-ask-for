SMS text messages

Also called: text messages, SMS alerts, send texts, 10DLC, SMS verification codes

Sending text messages through a provider's API. The code is easy. The work is registration (in the US, 10DLC brand and campaign approval for business texting), consent, STOP handling, cost per message, and fraud on verification codes.

You need it when

  • Time-sensitive reminders where email is too slow, like appointments and deliveries.
  • Users ask for texts and agree to get them.

Skip it when

  • Push notifications or email would do. SMS costs money per message and needs consent paperwork.
  • Login codes only. Authenticator apps or passkeys are cheaper and safer.

Ways to build it

  1. A messaging API per message plus registration fees

    Twilio, Vonage, Plivo, Telnyx and Amazon SNS or End User Messaging send and receive texts over HTTP.

    Tradeoff: Standard. US texting needs registration before delivery is reliable.

  2. A verification API per verification

    Twilio Verify, Vonage Verify and similar services handle codes, retries and some fraud blocking.

    Tradeoff: Less to build. Still pay per attempt, and fraud can run up the bill.

  3. A notification platform free tiers, then paid

    Novu, Knock or Courier route one notification to email, SMS or push based on user preferences.

    Tradeoff: One API for all channels. You still bring an SMS provider.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add SMS reminders with [provider].

Requirements:
- Collect phone numbers in E.164 format with an explicit, unchecked-by-default consent box that says what we'll text and how often. Store consent time and wording.
- Confirm the number with a one-time code before sending anything else.
- Every first message says who it's from and "Reply STOP to opt out". Handle STOP, START and HELP from the inbound webhook and stop all texts on STOP.
- Send from a background job, respect quiet hours in the user's timezone, and cap messages per user per day.
- Save delivery status callbacks and show failures in the admin.
- Rate limit verification codes per number and per IP, and block number ranges I don't serve, to prevent SMS pumping fraud.
- Keep the provider credentials in secrets, and log message ids, not message bodies with personal data.
- Note what registration I need (US 10DLC brand and campaign) before going live.

Acceptance checks (run each and show me the result):
1. Replying STOP stops all further texts and the app shows the user as opted out.
2. No text goes out between 9 PM and 8 AM in the user's timezone.
3. Hammering the send-code endpoint gets throttled.
4. Delivery failures show up in the admin.
5. Consent time and wording are stored for every number.

If you skip it

Carriers filter your texts, you text people who opted out, or bots run up a large bill through your verification form.

People describe this as

  • “text a reminder before an appointment”
  • “send a verification code by SMS”
  • “my texts aren't being delivered in the US”
  • “let users reply STOP”
