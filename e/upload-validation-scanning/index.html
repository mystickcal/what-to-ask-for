Upload validation and scanning

Also called: file upload security, file type check, magic bytes, virus scanning, malware scan, ClamAV

Checking every uploaded file on the server before you keep it: its real type from its bytes, its size, and its contents where that matters. Then store it under a name you choose and serve it so the browser can't run it as a page.

You need it when

  • Users can upload anything, and other people or your own code will open those files.

Skip it when

  • Never fully. Even avatar uploads need a type and size check.

Ways to build it

  1. Check type, size and structure in code $0

    Read the first bytes (python-magic, file-type for Node) and compare with an allowlist. Cap size and image pixels. Re-encode images with Pillow or sharp, which drops anything hidden in them.

    Tradeoff: Stops most problems cheaply. Doesn't detect known malware inside a valid file.

  2. Antivirus scan $0 self-hosted

    ClamAV (clamd) scans each file in a background job before it's marked ready.

    Tradeoff: Catches known malware. Needs memory and signature updates, and misses new threats.

  3. Storage provider scanning paid

    Managed malware scanning on your bucket from your cloud provider or a scanning service.

    Tradeoff: No servers to run. Costs per GB scanned.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Harden file uploads in [feature].

Requirements:
- Allow only [PDF, JPEG, PNG, WebP]. Detect the type from the file's bytes, not the extension or the Content-Type header. Reject anything else with a clear message.
- Cap size at [25 MB]. For images, refuse anything over [40] megapixels before fully decoding it.
- For zip-based files (DOCX, XLSX), cap the number of entries and the total expanded size, and reject paths containing ../.
- Store files under a random key you generate. Never use the uploaded file name as a path.
- Serve downloads with Content-Disposition: attachment and X-Content-Type-Options: nosniff, from storage or a separate domain, never as HTML on the app domain.
- Optional: scan with ClamAV in a background job and keep the file hidden until it passes.

Acceptance checks (run each and show me the result):
1. A .exe renamed to photo.jpg is rejected.
2. An HTML file uploaded as an image never renders as a page on the app domain.
3. A zip bomb is rejected quickly without filling the disk.
4. A file named ../../etc/passwd is stored under a random key.
5. If ClamAV is on, the EICAR test file is caught.

If you skip it

Stored cross-site scripting, malware passed on to other users, and servers knocked over by zip or image bombs.

How Derek runs it

Custody Journal checks file types from the bytes, caps uploads at 50 MB and refuses images over 40 million pixels. It inspects Office files' zip contents (entry count, expanded size, compression ratio, path traversal, macros) and parses PDFs in a separate process with an 8 second timeout. It doesn't run an antivirus scanner.

From the Custody Journal code and release runbook, read 2026-10-21.

People describe this as

  • “check that an uploaded file is really a PDF”
  • “a huge zip file crashed my server”
  • “only allow images and PDFs”
