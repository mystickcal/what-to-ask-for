Unsubscribe and suppression list

Also called: one-click unsubscribe, List-Unsubscribe header, email preferences, suppression list, bounce handling, spam complaints

A way for people to stop marketing email, honored quickly, plus a list of addresses you never mail again: unsubscribes, hard bounces and spam complaints. Gmail requires bulk senders to support one-click unsubscribe through the List-Unsubscribe and List-Unsubscribe-Post headers (RFC 8058).

You need it when

  • You send newsletters, digests, tips or any non-transactional email.

Skip it when

  • Purely transactional mail like receipts and password resets.

Ways to build it

  1. Let the email tool handle it included

    Listmonk, Postmark broadcast streams and most newsletter tools add the headers, host the unsubscribe page and keep a suppression list.

    Tradeoff: Easy. If your app also sends mail on its own, it must read that suppression list.

  2. Your own signed unsubscribe links $0

    A signed token holding the user id and email type. GET shows a confirm page, POST unsubscribes. The same URL goes in the List-Unsubscribe header.

    Tradeoff: Works across all your mail types. You build the preference page and suppression checks.

  3. Provider bounce and complaint webhooks $0

    Postmark, SES and Resend send events for bounces and complaints. Add those addresses to your suppression table.

    Tradeoff: Keeps your sender reputation healthy. Another webhook to verify and test.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add unsubscribe handling and a suppression list.

Requirements:
- Every non-transactional email has a visible unsubscribe link and the headers List-Unsubscribe: <https://...> and List-Unsubscribe-Post: List-Unsubscribe=One-Click.
- The link holds a signed token (user id plus email type). A POST to it unsubscribes with no login. A GET shows a confirm page and changes nothing, so link scanners can't unsubscribe people.
- A preferences page lets users turn each email type on or off.
- A suppression table stores unsubscribes, hard bounces and spam complaints from the provider's webhooks. Every send checks it first.
- Unsubscribes take effect before the next send.

Acceptance checks (run each and show me the result):
1. curl -X POST to the List-Unsubscribe URL unsubscribes the user with no cookies.
2. A GET to the same URL doesn't change anything.
3. A tampered token returns 404.
4. An address marked as a hard bounce is skipped on the next send.
5. Turning off one email type in preferences keeps the others.

If you skip it

Spam complaints rise, Gmail and Yahoo start filtering all your mail, and you risk breaking laws like CAN-SPAM.

How Derek runs it

Custody Journal's digest and tips emails link to signed unsubscribe tokens that expire after 180 days. Opening the link shows a confirm page and changes nothing. Only the POST turns the email off, so mail scanners that prefetch links can't unsubscribe anyone.
