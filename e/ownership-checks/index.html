Ownership checks (IDOR)

Also called: IDOR, insecure direct object reference, broken object level authorization, BOLA, object-level authorization

Checking on every request that the logged-in user is allowed to touch the exact record they asked for. The usual bug: the code loads a record by id and never checks who owns it. Hard-to-guess ids help but don't replace the check.

You need it when

  • Any URL or API with a record id in it.

Skip it when

  • The record is public on purpose.

Ways to build it

  1. Put the owner in the query $0

    Load records with the owner in the filter, like get(id=..., owner=current_user), so another user's id finds nothing and returns 404.

    Tradeoff: Simple and hard to get wrong once it's a habit. Every new endpoint must follow it.

  2. A scoped helper or manager $0

    One function, for_user(user), that every query starts from. Code review flags any query that doesn't use it.

    Tradeoff: Makes the safe path the easy path. Admin and background code need a clearly named way around it.

  3. Database row level security $0

    Postgres RLS policies as a backstop, so even a buggy query can't return other users' rows.

    Tradeoff: Strong. Needs the user identity passed into the database session.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Audit and fix object-level authorization in this app.

Requirements:
- List every route and API endpoint that takes a record id (path, query string or body).
- For each, load the record with the current user (or their tenant) in the query. Another user's id must return 404, not the record and not a 403 that confirms it exists.
- Check nested ids too, like an attachment id inside a request for a note the user owns.
- Writes and deletes get the same check as reads.
- Add a test per endpoint: user A creates a record, user B tries to read, edit and delete it.
- Produce a table of endpoints with the check used and the test name.

Acceptance checks (run each and show me the result):
1. User B gets 404 for user A's record on every endpoint in the table.
2. Changing an id inside a JSON body (not only the URL) is blocked.
3. File and download endpoints check ownership the same way.
4. List endpoints never include other users' rows, even with filters changed.
5. The test suite covers every endpoint in the table.

If you skip it

Anyone can read or change other users' records by counting up ids. Broken object level authorization is the first item on the OWASP API Security Top 10.

How Derek runs it

Custody Journal loads user records with the owner in the query, for example get_object_or_404(Entry, pk=pk, user=request.user), so another user's id returns 404.
