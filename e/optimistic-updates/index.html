Optimistic updates

Also called: optimistic UI, instant UI updates, useOptimistic, rollback on error, snappy UI

Showing the result of an action on screen the moment the user clicks, then sending it to the server in the background. If the server says no, you put the old value back and tell the user. It makes small actions like likes, checkboxes and reordering feel instant.

You need it when

  • Small, common actions that almost always succeed, like toggles, likes, renames and reordering.
  • Users notice a delay between clicking and seeing the change.

Skip it when

  • Payments, deletes of important data, or anything where showing success and then taking it back would hurt or confuse people. Show a clear pending state there instead.

Ways to build it

  1. Your data library's optimistic option $0

    TanStack Query's onMutate with rollback in onError, SWR's optimisticData, or the cache update in Apollo or RTK Query.

    Tradeoff: Handles caching, rollback and refetching for you. Each action still needs its own update code.

  2. React useOptimistic $0

    Wrap the state you show in useOptimistic and set the new value before the server action runs.

    Tradeoff: Built in and small. Works best with React server actions and forms.

  3. Write it by hand $0

    Save the old value, set the new one, send the request, and put the old value back if it fails.

    Tradeoff: No library needed. Easy to miss the out-of-order and double-click cases.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Make these actions update the UI optimistically: [like button / todo checkbox / rename / reorder].

Requirements:
- Update the screen immediately when the user acts, then send the request in the background.
- Keep the previous value. If the request fails or times out, restore it and show a short error the user can see.
- After the request settles, refetch or replace with the server's version so the screen matches the database.
- If the user clicks again before the first request finishes, the last click wins and the screen never flickers between old states.
- Do not use optimistic updates for [payments / deletes / anything listed here]. Show a pending state there instead.
- Use [TanStack Query / SWR / useOptimistic / the existing data layer] and follow its documented rollback pattern.

Acceptance checks (run each and show me the result):
1. Clicking like (or done) updates the screen right away, before the server answers.
2. With the network throttled to Slow 3G in dev tools, the change still shows instantly.
3. When the server returns an error, the screen goes back to the old value and shows a message.
4. Clicking the same button five times fast ends with the right final state after a refresh.

If you skip it

Every click waits on a round trip, so the app feels sluggish even when the server is fine. Done badly, you get the opposite problem: changes that look saved but quietly were not.

People describe this as

  • “my app feels slow every time I click a button”
  • “the like button waits for the server before it changes”
  • “make my UI feel instant”
