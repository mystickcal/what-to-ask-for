Image resizing and thumbnails

Also called: thumbnails, image optimization, responsive images, image transforms, image CDN

Making smaller copies of uploaded images at the sizes your pages show, in modern formats, so pages load fast. Do it once when the image arrives, or on request through an image service that caches the result.

You need it when

  • Users upload photos and you show them in lists, cards or avatars.

Skip it when

  • You only show a few images you made yourself. Export them at the right size once.

Ways to build it

  1. Resize on upload $0

    A background job uses sharp (Node) or Pillow (Python) to write a few fixed sizes, like 200, 800 and 1600 px wide, as WebP or AVIF next to the original.

    Tradeoff: Cheap to serve. Adding a new size later means reprocessing old images.

  2. Self-hosted image proxy $0 + server

    imgproxy or thumbor resizes on request from a URL with the size in it. Put a CDN in front so each size is made once.

    Tradeoff: Any size, any time. Sign the URLs so strangers can't make your server render huge images.

  3. Managed image service paid, free tiers

    Cloudflare Images, Cloudinary, imgix, or your host's built-in optimizer (for example next/image on Vercel).

    Tradeoff: Least work. Priced per image or per transform, which grows with traffic.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add thumbnails and responsive images for user uploads in [feature].

Requirements:
- When an image is uploaded, a background job creates [200, 800, 1600] px wide versions in WebP, keeping the aspect ratio. Never upscale.
- Apply the EXIF orientation before resizing so phone photos aren't sideways. Strip EXIF metadata (including GPS location) from the resized copies.
- Refuse images over [40] megapixels before decoding them fully, to avoid decompression bombs.
- Store the sizes with predictable keys next to the original and record them in the database.
- In the HTML, use srcset and sizes so the browser picks the smallest file that fits, with width and height set to avoid layout shift, and loading="lazy" below the fold.
- Until the job finishes, show a placeholder, not the full original.

Acceptance checks (run each and show me the result):
1. A 12 MB phone photo shows in a list as a file under 100 KB.
2. A photo taken in portrait shows the right way up.
3. The resized files have no GPS data (check with exiftool).
4. A 20,000 x 20,000 px image is refused without the worker running out of memory.
5. Lighthouse shows no 'properly size images' warning on the page.

If you skip it

Slow pages and big bandwidth bills from full-size photos, sideways pictures, and leaked home locations in photo metadata.

How Derek runs it

For each uploaded image, Custody Journal stores an encrypted 400 px JPEG thumbnail (quality 82) made with Pillow. It keeps the EXIF capture time and location on purpose, because those details can matter as evidence.
