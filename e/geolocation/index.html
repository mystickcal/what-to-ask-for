Location and distance search

Also called: geolocation, near me search, geocoding, distance search, PostGIS, maps

Storing latitude and longitude for things, turning addresses into coordinates (geocoding), and querying by distance with a spatial index. The user's own location comes from the browser with permission, or from a typed address or postcode.

You need it when

  • "Near me" search, delivery zones, local listings, check-ins, or maps.

Skip it when

  • City or region dropdowns are enough. Exact location is sensitive data, so don't collect it without a reason.

Ways to build it

  1. PostGIS $0

    Add the PostGIS extension, store a geography(Point) column with a GiST index, and query with ST_DWithin and ST_Distance.

    Tradeoff: Accurate and fast at scale. One extension to install (most hosted Postgres offers it).

  2. Your search engine's geo features $0 self-hosted

    Meilisearch, Typesense and Elasticsearch filter and sort by distance from a point.

    Tradeoff: Great when search already lives there. Another index to keep in sync.

  3. Geocoding APIs free tiers, then per request

    Google Maps Platform, Mapbox, or open data via Nominatim (with its usage policy) or a self-hosted Photon or Pelias.

    Tradeoff: Needed to turn addresses into points. Check terms: some forbid storing results or using them off their maps.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add location search so users can find [things] near them.

Requirements:
- Store location as [PostGIS geography(Point, 4326)] with a GiST index.
- Geocode addresses when records are saved, in a background job, with [provider]. Save the coordinates and the provider's place id if the terms allow storing it.
- User location: a typed address or postcode first. Offer "use my location" with the browser Geolocation API only on click, and handle denial.
- Query by radius with ST_DWithin and sort by ST_Distance. Paginate.
- Show distances in miles or km by locale.
- Don't store the user's precise location unless needed. Round it in logs and analytics.
- Respect the geocoding provider's rate limits and caching rules.

Acceptance checks (run each and show me the result):
1. A search 10 miles from a point returns only items inside that radius, nearest first.
2. The query uses the spatial index (EXPLAIN shows it).
3. Denying location permission falls back to typing a place.
4. Logs don't contain precise user coordinates.
5. Geocoding failures don't block saving a record.

If you skip it

Distance search scans every row and slows down, or you quietly collect precise location you didn't need.

People describe this as

  • “show places near the user”
  • “find all stores within 10 miles”
  • “turn an address into coordinates”
  • “sort results by distance”
