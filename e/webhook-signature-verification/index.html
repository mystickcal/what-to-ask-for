Webhook signature verification

Also called: webhook signing, HMAC signature, signing secret, Stripe-Signature header

A webhook is another service calling your URL when something happens. The sender signs each request with a shared secret. Your server recomputes the signature from the raw body and rejects anything that doesn't match or is too old.

You need it when

  • A webhook changes anything: payments, plan changes, orders, form submissions.

Skip it when

  • Don't skip it for anything that changes data. Even if you re-fetch the object from the API, verify first so strangers can't trigger work.

Ways to build it

  1. The provider's SDK helper $0

    Stripe: stripe.Webhook.construct_event in Python, stripe.webhooks.constructEvent in Node. Test locally with the Stripe CLI: stripe listen --forward-to and stripe trigger.

    Tradeoff: Simplest and correct, but it needs the raw request body. Frameworks that parse JSON first break the signature.

  2. HMAC-SHA256 by hand $0

    For providers without an SDK (for example GitHub's X-Hub-Signature-256), compute the HMAC of the raw body and compare with hmac.compare_digest or crypto.timingSafeEqual.

    Tradeoff: Easy to get subtly wrong: plain string compare, wrong encoding, or no timestamp check.

  3. A webhook gateway free tiers

    Hookdeck or Svix receive, verify, queue and retry webhooks, then forward them to you.

    Tradeoff: Another hop and account. Useful when you receive from many providers.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add a webhook endpoint at [path] for [provider].

Requirements:
- Read the raw request body before any JSON parsing.
- Verify the signature with the provider's SDK (or HMAC-SHA256 with a constant-time compare). The secret comes from an environment variable.
- Enforce the timestamp tolerance so old requests can't be replayed (Stripe's libraries default to 5 minutes).
- Reject bodies over [1 MB] with 413 and bad signatures with 400, before touching any data.
- Exempt only this route from CSRF.
- Log the event id and type only. Never log the payload, headers or secret.

Acceptance checks (run each and show me the result):
1. A request with no signature returns 400 and changes nothing.
2. A correctly signed request with one byte of the body changed returns 400.
3. stripe trigger checkout.session.completed through the Stripe CLI returns 200.
4. Replaying an old signed request outside the tolerance returns 400.
5. The secret appears only in environment config, not in code, logs or the frontend.

If you skip it

Anyone who finds the URL can mark orders paid or upgrade accounts for free.

How Derek runs it

Custody Journal's Stripe endpoint returns 413 for bodies over 1 MB, verifies with stripe.Webhook.construct_event, and returns 400 on a bad signature before any data changes. For the webhooks it sends to other systems, it signs the body with HMAC-SHA256 in an X-Webhook-Signature header and checks destination URLs with an SSRF guard.
