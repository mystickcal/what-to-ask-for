Sanitizing user HTML and markdown (XSS)

Also called: XSS prevention, cross-site scripting, HTML sanitizer, rich text safety, output escaping

Making sure text users write can't run as code in other people's browsers. Escape by default everywhere, and when you must allow formatting, run the HTML through an allowlist sanitizer on the server before saving or showing it.

You need it when

  • Users can enter rich text, markdown, comments, bios or anything shown to other users.
  • AI output is rendered as HTML or markdown.

Skip it when

  • Never for escaping. The sanitizer is only needed when you allow markup.

Ways to build it

  1. Template auto-escaping $0

    React, Django, Jinja, Rails and most templates escape by default. Don't bypass it (dangerouslySetInnerHTML, |safe, html_safe, v-html) with user data.

    Tradeoff: Covers most cases free. Every bypass needs review.

  2. An allowlist HTML sanitizer $0

    nh3 or bleach (Python), DOMPurify (browser or Node with jsdom), sanitize-html (Node), Loofah (Ruby). Allow only the tags and attributes your editor makes.

    Tradeoff: Lets formatting through safely. Keep the allowlist small and links limited to http, https and mailto.

  3. CSP as a backstop $0

    A Content-Security-Policy without 'unsafe-inline' blocks many injected scripts even if sanitizing misses.

    Tradeoff: Strong extra layer. Needs inline scripts removed first.

Audit and fix cross-site scripting risks where users can enter text.

Requirements:
- List every place user or AI text is shown, and every template or component that bypasses escaping.
- Remove bypasses where plain text is enough.
- Where formatting is needed, sanitize on the server with [nh3 / DOMPurify / sanitize-html] using an allowlist that matches the editor's tags. Sanitize on save and again on render if old data exists.
- Allow only http, https and mailto links. Add rel="noopener noreferrer" to links and drop target.
- Strip event handler attributes, style, iframe, object, embed and svg unless needed.
- Render markdown with raw HTML disabled, then sanitize the output.
- Add tests with common payloads (script tags, img onerror, javascript: links, svg onload).

Acceptance checks (run each and show me the result):
1. Saving <img src=x onerror=alert(1)> shows the text or a broken image, never an alert.
2. A javascript: link is removed or made inert.
3. Bold, lists and links from the editor still render.
4. Searching templates finds no unreviewed escaping bypasses.
5. AI-generated markdown with HTML in it is sanitized too.

If you skip it

One user's profile or comment runs a script in every visitor's browser and can act as them.

How Derek runs it

Custody Journal cleans journal entry HTML from its rich text editor with nh3, using an allowlist of the editor's tags and allowed link schemes, and stamps rel="noopener noreferrer" on every link.
