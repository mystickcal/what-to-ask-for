Input validation

Also called: server-side validation, schema validation, mass assignment, allowlist, SQL injection prevention

Checking every piece of incoming data on the server against what you expect: type, length, format and allowed values. Anything else is rejected before your code uses it. Browser checks only help the user. Anyone can skip them.

You need it when

  • Every form, API endpoint, webhook and file import.

Skip it when

  • Never on the server. Even internal endpoints get called with bad data eventually.

Ways to build it

  1. A schema at each endpoint $0

    Zod or Valibot (TypeScript), Pydantic (Python) or JSON Schema. Parse the body into the schema and use only the parsed result.

    Tradeoff: Clear and typed. You need the habit of never reading the raw body after parsing.

  2. Your framework's forms or serializers $0

    Django forms or DRF serializers with explicit field lists, Rails strong parameters, Laravel validation.

    Tradeoff: Built in. 'All fields' shortcuts bring back mass assignment.

  3. Database constraints as the last line $0

    NOT NULL, CHECK constraints, foreign keys, unique indexes and column lengths.

    Tradeoff: Catches what code misses. Errors arrive late and are less friendly.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Add server-side input validation to [endpoints/forms].

Requirements:
- Define a schema for each endpoint's input: types, required fields, max lengths, allowed values, number ranges.
- Reject unknown fields. Never copy request data straight onto a model. Set allowed fields one by one (no mass assignment of role, owner_id, is_admin or price).
- Cap request body size at [1 MB] unless the endpoint needs more.
- Use parameterized queries or the ORM everywhere. No SQL built from strings.
- Return 400 with a field-by-field message the UI can show. Don't echo raw input back into HTML.
- Add database constraints for the rules that must never break.

Acceptance checks (run each and show me the result):
1. Sending is_admin=true or a different owner_id in the body changes nothing.
2. A 10,000-character name is rejected with a clear message.
3. A body over the size cap returns 413.
4. Searching for ' OR 1=1 -- returns a normal empty result.
5. Every endpoint in the app is listed with its schema.

If you skip it

People give themselves admin rights, store junk that breaks pages, or crash the server with huge requests.

People describe this as

  • “users can send any data to my API”
  • “someone made themselves admin by adding a field to the request”
  • “validate form data on the server too”
  • “a huge request crashed my server”
