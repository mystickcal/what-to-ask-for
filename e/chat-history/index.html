AI chat history storage

Also called: conversation memory, chat threads, message history, context window management, AI conversations

Tables for conversations and messages, plus a rule for how much history goes back to the model each turn. Older turns get trimmed or summarized so long chats stay inside the context window and the cost stays sane.

You need it when

  • Users have multi-turn chats with your AI and expect them to persist.

Skip it when

  • Single-shot AI features with no follow-up questions.

Ways to build it

  1. Conversations and messages tables $0

    conversation (owner, title, created, last message) and message (role, content, tokens, created). Send the last N messages each turn.

    Tradeoff: Simple, private and queryable. You handle trimming and summaries.

  2. Your provider's stored conversations token and storage costs

    Some APIs, such as OpenAI's Conversations and Responses APIs, can keep conversation state for you.

    Tradeoff: Less code. Data lives with the provider and retention follows their rules.

  3. A memory layer free tiers or open source

    Tools like Mem0 or Zep pull out facts and summaries to recall across chats.

    Tradeoff: Long-term memory. Extra cost and extra privacy questions.

Prompt for your coding agent

Replace the [bracketed] parts. Works in Claude Code, Cursor or Codex.

Store AI chat history and manage how much of it goes to the model.

Requirements:
- Tables: conversation (id, owner, title, created, last_message_at, archived) and message (id, conversation, role, content, token count, model, created).
- Only the owner can read, rename or delete a conversation. Deleting removes its messages.
- Each turn, send the system prompt, a running summary of older turns if any, and the last [10] messages, kept under [N] tokens.
- When history passes the limit, summarize the oldest turns into the running summary in a background step.
- Auto-title new conversations from the first message.
- Count tokens per message for cost tracking.
- Respect data retention: [delete or archive after X days], and include chats in data export and account deletion.

Acceptance checks (run each and show me the result):
1. Refreshing the page shows the full conversation.
2. A 200-message chat still gets answers without context-length errors.
3. Another user can't open the conversation URL.
4. Deleting a chat removes its messages from the database.
5. Account export includes chats.

If you skip it

Users lose chats on refresh, long chats crash with context errors, or private conversations leak to other users.

How Derek runs it

Custody Journal stores AI chats as conversation and message rows with the role, content and tokens used. Messages can link to the journal entries, documents and events they referenced, and each new question sends the last 10 messages as history.
